# 订单状态查询适配协议

当前没有你的电商接口文档，因此项目提供的是通用网关协议，尚未接通任何电商平台。不能把 COMMERCE_BASE_URL 直接填成淘宝、京东或拼多多的网站地址。

拿到真实接口后，可修改 `qqbot/reconcile.py` 中的查询请求和字段映射，或部署一个实现以下协议的授权网关。签名、商家授权、分页和限流必须按实际平台文档实现。

```http
GET /orders/00012345678901234567?shop=示例旗舰店
Authorization: Bearer <COMMERCE_API_KEY>
```

成功返回 200 和以下 JSON，金额以人民币元表示，使用两位小数的字符串。退款金额为累计已到账退款，不是此次退款增量。

```json
{
  "order_no": "00012345678901234567",
  "shop": "示例旗舰店",
  "ordered_on": "2026-10-01",
  "order_amount": "129.00",
  "paid_amount": "99.90",
  "refund_amount": "20.10",
  "status": "部分退款",
  "currency": "CNY"
}
```

每次必须返回店铺、订单号、最新状态和累计退款金额。店铺和订单号必须与查询对象完全一致。日期、订单金额和实付款可以省略，保留账本已有值；不能通过省略退款金额表示零退款。

合法状态：待付款、待发货、待收货、已完成、退款中、部分退款、已退款、已取消。未知状态、无授权、查不到订单、网络失败和数据冲突都保持待核对，不更新权威核验时间，不把未知状态改成已完成。

全量核对会遍历当前所有订单，逐笔验证并保存失败清单。仅当全部订单成功核验才记录 `last_full_reconcile_completed`。没有接口时，可在 `/docs` 上传 UTF-8 CSV；样例在 `examples/store-orders.csv`。CSV 仅更新已有订单，以店铺和订单号匹配客户归属，未知订单会报错，不能依靠订单号猜客户。
